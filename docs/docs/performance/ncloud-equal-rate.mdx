The measured 0.15 candidate (`4aabf09`) is compared with **aerospike-py 0.14.4** and the official **Aerospike Python SDK 1.0.0** (`aerospike-sdk`).

## NumPy batch reads {#changes-in-015}

On two Ncloud Linux VMs, each client read eight integer bins into a structured NumPy array. Standard CPython targeted 60,000 rows/s and free-threaded CPython 90,000 rows/s. **All three metrics ↓ lower is better.**

## Measurement conditions {#workload-and-metrics}

- Ncloud KR-1, two 4-vCPU, 16 GiB Ubuntu 24.04 VMs on one subnet. Aerospike CE 8.2.0.1 ran on a single node with a 1 GiB in-memory namespace.
- CPython 3.14.2 and 3.14.2t, NumPy 2.5.5. aerospike-py used `batch_read().to_numpy(dtype)`. The SDK used `session.query(*keys).execute()`, `collect()` and `numpy.fromiter()`. Each client used zero retries.
- Up to four synchronous requests in flight. Three runs per condition in fresh processes. CPU per row and Linux peak RSS include all client threads. Each is a median across runs. Pooled p99 covers scheduled arrival through array conversion and validation.
- Regular Python completed 1,050 calls per client and size. Free-threaded CPU and latency used 1,200 scheduled calls, with 180 calls in a shorter run for RSS.

### Time to convert the result

For one 2,000-key request at a time on free-threaded CPython, median NumPy conversion took **1.89 ms** in both aerospike-py versions and **4.28 ms** in the official SDK. All 206 sampled Python batch spans from 0.15 matched a Rust `BATCH_READ` child span.

<img src={useBaseUrl('/benchmark/4aabf09/ncloud/trace-phases.png')} alt="Free-threaded diagnostic bar charts separate the time from submit to API return and NumPy conversion at all three sizes. The SDK's NumPy conversion reaches 4.28 milliseconds at 2,000 keys compared with 1.89 for both aerospike-py builds." />

### Optimization probes {#optimization-candidates}

In a separate 2,000-key async run, the Rust batch call averaged **10.79 ms**, key parsing **1.20 ms**, and NumPy conversion **1.44 ms**, including **0.22 ms** to build the key index. Reusing digests reduced key parsing in both trials, while total latency improved in one trial. The Rust batch timer includes routing, transport, server work and decoding.
