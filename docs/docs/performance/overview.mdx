The measured 0.15 candidate (`4aabf09`) is compared with **aerospike-py 0.14.4** and the official **Aerospike Python SDK 1.0.0** (`aerospike-sdk`). [Measured build](https://github.com/aerospike-ce-ecosystem/aerospike-py/commit/4aabf09f7ca1911a5ba00a3d668ec799c19ed54c) · [Official SDK](https://github.com/aerospike/aerospike-client-python-sdk/releases/tag/v1.0.0)

## Batch read and write throughput {#batch-throughput}

Four threads on an M4 Pro processed 720 keys per batch. **Rows/s ↑ higher is better.** Percentages show the change in 0.15 relative to each baseline.

| CPython | Workload | vs. 0.14.4 | vs. official SDK |
| --- | --- | ---: | ---: |
| Standard | NumPy read | +13.7% | +34.3% |
| Standard | NumPy write | +17.9% | +18.6% |
| Standard | Dictionary read | +5.3% | +19.2% |
| Standard | Dictionary write | +7.5% | +15.7% |
| Free-threaded | NumPy read | +18.8% | +17.3% |
| Free-threaded | NumPy write | +11.6% | +16.8% |
| Free-threaded | Dictionary read | +3.3% | +4.0% |
| Free-threaded | Dictionary write | −2.3% | −16.4% |

[Throughput in rows/s and client APIs](./client-comparison.md)

## 2,000-key NumPy reads at equal throughput

In the Ncloud repeat, standard CPython processed 60,000 rows/s and free-threaded CPython processed 90,000 rows/s. **CPU time, peak resident memory (RSS) and p99 latency ↓ lower is better.**

| CPython | Metric ↓ | vs. 0.14.4 | vs. official SDK |
| --- | --- | ---: | ---: |
| Standard | CPU time per row | −6.1% | −38.7% |
| Standard | Peak RSS | +10.7% | −34.7% |
| Standard | p99 latency | −1.9% | −47.6% |
| Free-threaded | CPU time per row | −1.7% | −43.1% |
| Free-threaded | Peak RSS | +7.3% | −40.2% |
| Free-threaded | p99 latency | +1.9% | −48.9% |

[500-, 1,000- and 2,000-key results](./ncloud-equal-rate.mdx) · [Memory at higher concurrency](../guides/migration-0.15.md#memory-under-concurrent-batch-load)

## Async queries {#async-queries}

For 12,000 records, 0.15 reduced async list collection time by **38.7%** on standard CPython and **22.6%** on free-threaded CPython compared with 0.14.4. With `async for`, the official SDK took **9.97×** and **4.70×** as long as 0.15, respectively. The public async iterator was introduced in 0.15.
