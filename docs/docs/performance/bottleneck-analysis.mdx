The [Ncloud batch-read benchmark](./ncloud-equal-rate.mdx) measures CPU, memory and p99 at matched completed throughput. Its OTLP experiment traces the batch read and times NumPy conversion separately.

The April 2026 serving experiment read nine sets of 200 keys per HTTP request. The application timed the complete fan-out, while the client's histograms timed stages within each individual `batch_read()`. The nine requests can overlap. Adding their stage averages cannot reconstruct one HTTP request's elapsed time. The archived profiling report identifies the clients as development `aerospike-py v0.1.0` and C extension `aerospike 19.2.0`. [April report](https://github.com/aerospike-ce-ecosystem/aerospike-py/blob/524cadf9d5864ed8aeeabdfca88861eca4113cfe/benchmark/results/bottleneck-analysis.md)

| Timing boundary | What it includes |
|---|---|
| HTTP request | Key construction, all database calls, output conversion, inference and response |
| One `batch_read()` | Its wait for admission, client work and the Aerospike operation |
| Materialization | Work done after the lazy handle returns when the consumer calls `to_dict()` or `to_numpy()` |

The 3.11/3.14t curl experiment observed mean `spawn_blocking_delay` of 234 and 0.12 ms respectively. The 3.11 run reached memory pressure and there were too few FT samples of `event_loop_resume_delay` to compare. For the load configuration and recorded metrics see the [archived serving profile](./production-benchmark#what-gets-faster-and-why).

## Profiling a new run {#what-this-page-will-cover-when-re-measured}

1. Choose the user's latency boundary. For an endpoint consuming NumPy results, time through `to_numpy()` and the downstream use of the array. Record successful rows and errors alongside elapsed time.
2. Use `AEROSPIKE_PY_INTERNAL_METRICS=1` or the scoped Python context manager to collect `db_client_internal_stage_seconds`. Compare `limiter_wait`, `io` and the output-conversion stage for the same operation and load. [Stage definitions and activation](../integrations/observability/internal-stage-metrics.md)
3. For fan-out, run `/s4/gather` and `/s4/single` with the same total number of keys. Record HTTP p95 and errors alongside batch call counts. [Local ASGI scenarios](./isolated-benchmark)

For the current CPython 3.14.2 batch data see [Client comparison](./client-comparison). For the query iterator's per-row versus grouped completion path see [Async stream profile](./async-stream-profile).
