로컬 `benchmark/` 스위트는 `aerospike-py.AsyncClient`와 `asyncio.to_thread()`에서 실행한 동기 `aerospike` C 확장을 비교합니다. FastAPI 엔드포인트가 레코드를 읽고 건수나 합계를 반환하므로 HTTP 처리, 데이터 변환, 해당 경로의 추론 시간이 측정에 포함됩니다. `aerospike-py 0.14.4`, 개선 버전, 공식 `aerospike-sdk 1.0.0`을 직접 호출한 결과는 [클라이언트 비교](./client-comparison)에 있습니다.

## 스모크 실험 실행 {#실행-방법}

저장소 루트에서 로컬 CE 8.1.2.1_3을 18710 포트에 띄우고 `test/bench`에 데이터를 넣습니다. uv, Podman, HTTP 부하 도구 oha를 사용합니다. Docker Compose를 사용하는 경우 `RUNTIME=docker`를 지정합니다.

```bash
cd benchmark
make sync PYTHON=3.11
make up
make seed
make bench-all CONCURRENCY=4 DURATION=3s BATCH_SIZE=30
make report
```

실행 스크립트는 엔드포인트별로 클라이언트를 교대하며 uvicorn worker 하나를 실행합니다. `/healthz`가 응답하면 지정한 시간만큼 요청을 보내고, `benchmark/results/` 아래에 `meta.json`과 `oha.json`을 저장합니다. `make report`는 비교 표를 출력합니다. [발표 당시 실행 코드](https://github.com/aerospike-ce-ecosystem/aerospike-py/tree/7c6c0cec741e0a9ce65ab12e0375f83fad870c97/benchmark)

## 당시 스모크 결과 {#시나리오}

2026년 5월 27일 공개된 결과는 Python 3.11, 예열된 캐시, 동시 HTTP 요청 4개, 배치당 30키, 실행 시간 3초 조건입니다. S4에서는 30키씩 4그룹을 사용했습니다. 보고서는 C 라이브러리를 19.x로 표기하고 정확한 패키지 빌드나 실행별 oha 표본은 제공하지 않습니다. 위 명령으로 다시 측정하면 현재 체크아웃과 uv가 설치한 패키지를 사용합니다. [당시 발표한 표](https://github.com/aerospike-ce-ecosystem/aerospike-py/blob/7c6c0cec741e0a9ce65ab12e0375f83fad870c97/docs/docs/performance/isolated-benchmark.mdx)

| 엔드포인트 | C 요청/초 | aerospike-py 요청/초 | C 평균 / p95 (ms) | aerospike-py 평균 / p95 (ms) |
|---|---:|---:|---:|---:|
| S1 · 적중 건수 | 2,383.2 | 2,466.8 | 1.68 / 2.14 | 1.62 / 2.39 |
| S2 · dict에서 추론 | 1,986.0 | 2,206.6 | 2.01 / 2.48 | 1.81 / 2.56 |
| S3 · NumPy에서 추론 | 1,854.0 | 2,466.2 | 2.16 / 2.75 | 1.62 / 2.36 |
| S4 · gather | 902.8 | 1,130.3 | 4.43 / 4.80 | 3.54 / 4.95 |
| S4 · 단일 호출 | 996.1 | 1,385.4 | 4.02 / 4.70 | 2.89 / 4.24 |
| S5 · 필드 8개 소비 | 2,421.4 | 2,722.0 | 1.65 / 2.09 | 1.47 / 2.16 |

### S1 · 성공한 행 수 계산 {#s1--순수-batch_read-라운드트립}

양쪽 모두 레코드를 읽습니다. aerospike-py는 반환 핸들의 네이티브 `found_count()`를 호출하고, C 어댑터는 Python 배치 행을 순회하며 결과 코드를 검사합니다. 이 부하에서 aerospike-py의 평균은 더 낮았고 p95는 더 높았습니다. [엔드포인트 코드](https://github.com/aerospike-ce-ecosystem/aerospike-py/blob/7c6c0cec741e0a9ce65ab12e0375f83fad870c97/benchmark/src/app/routes/s1_read_only.py)

</TabItem>

### S2 · dict에서 텐서 만들기 {#s2--batch_read--dict--tensor--dlrm}

양쪽 모두 특성 값 64개를 Python 행으로 만들고 누락된 레코드는 0으로 채운 뒤 float32 텐서를 만들어 같은 2층 모델을 실행합니다. aerospike-py는 `to_dict()`를 사용하고 C 어댑터는 반환된 행의 bin을 읽습니다. [엔드포인트 코드](https://github.com/aerospike-ce-ecosystem/aerospike-py/blob/7c6c0cec741e0a9ce65ab12e0375f83fad870c97/benchmark/src/app/routes/s2_dict_infer.py)

</TabItem>
<TabItem value="s3" label="S3 · NumPy에서 추론">

### S3 · NumPy 행렬에서 텐서 만들기 {#s3--batch_read--numpy-structured-array--torch--dlrm}

`to_numpy(dtype)`가 구조화 배열을 할당하고 값을 채웁니다. 이후 float32 뷰와 reshape, `torch.from_numpy()`가 같은 메모리를 공유합니다. C 어댑터는 각 행의 dict에서 값을 꺼내 행렬을 채운 뒤 같은 모델을 호출합니다. 이 전체 경로를 포함한 처리량은 aerospike-py 초당 2,466건, C 초당 1,854건이었습니다. [엔드포인트 코드](https://github.com/aerospike-ce-ecosystem/aerospike-py/blob/7c6c0cec741e0a9ce65ab12e0375f83fad870c97/benchmark/src/app/routes/s3_numpy_infer.py)

</TabItem>
<TabItem value="s4" label="S4 · gather와 단일 배치">

### S4 · 네 배치와 통합 배치 {#s4--asynciogathern-batch_reads-vs-단일-batch_readmixed-keys}

`/s4/gather`는 30키짜리 호출 4개를 동시에 제출하고, `/s4/single`은 120키를 한 번에 제출합니다. C 어댑터는 각 호출을 스레드 풀에서 실행합니다. 이 실험에서는 두 클라이언트 모두 단일 호출의 평균과 p95가 낮았습니다. [엔드포인트 코드](https://github.com/aerospike-ce-ecosystem/aerospike-py/blob/7c6c0cec741e0a9ce65ab12e0375f83fad870c97/benchmark/src/app/routes/s4_gather_vs_single.py)

</TabItem>
<TabItem value="s5" label="S5 · 일부 필드">

### S5 · 특성 필드 8개 읽기 {#s5--lazybatchrecords-의-부분-materialisation}

두 클라이언트 모두 모든 bin을 요청합니다. aerospike-py는 특성 필드 64개 중 8개로 구성된 구조화 dtype을 채우고, C 어댑터는 반환된 dict에서 8개 필드 값을 읽습니다. 두 엔드포인트 모두 합계와 적중 레코드 수를 반환합니다. [엔드포인트 코드](https://github.com/aerospike-ce-ecosystem/aerospike-py/blob/7c6c0cec741e0a9ce65ab12e0375f83fad870c97/benchmark/src/app/routes/s5_lazy_subset.py)

## 측정 범위 {#의도적으로-측정-안-한-것}

응답 본문에는 적중 건수나 집계값이 들어가며 처리량 단위는 전체 HTTP 요청/초입니다. 배치 호출만 재는 실험의 초당 행 수와 직접 비교할 수 없습니다. 배포된 추론 서비스의 HTTP 수치는 [4월 서빙 벤치마크](./production-benchmark)에 있습니다.

## Free-threaded Python 결과 {#python-314t--같은-스위트-위-런타임-swap}

이 ASGI 스모크 결과는 일반 Python 3.11에서 측정했습니다. 같은 CPython 버전의 일반·FT 빌드를 비교한 [3.14.2 클라이언트 결과](./client-comparison)와 쿼리 순회 및 이벤트 루프 깨우기 동작을 분석한 [비동기 스트림 프로파일](./async-stream-profile)을 함께 볼 수 있습니다.
