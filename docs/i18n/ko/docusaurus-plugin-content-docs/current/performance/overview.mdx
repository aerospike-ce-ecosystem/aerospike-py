aerospike-py 0.15 후보판(`4aabf09`)을 **직전 버전 0.14.4**, **공식 Aerospike Python SDK 1.0.0**(`aerospike-sdk`)과 비교했습니다. [측정 빌드](https://github.com/aerospike-ce-ecosystem/aerospike-py/commit/4aabf09f7ca1911a5ba00a3d668ec799c19ed54c) · [공식 SDK](https://github.com/aerospike/aerospike-client-python-sdk/releases/tag/v1.0.0)

## 배치 읽기·쓰기 처리량 {#batch-throughput}

M4 Pro에서 스레드 4개로 호출당 720키를 처리했습니다. **초당 처리 행 수 ↑ 높을수록 좋습니다.** 각 열은 비교 대상 대비 0.15의 변화율입니다.

| CPython | 작업 | 0.14.4 대비 | 공식 SDK 대비 |
| --- | --- | ---: | ---: |
| 일반 | NumPy 읽기 | +13.7% | +34.3% |
| 일반 | NumPy 쓰기 | +17.9% | +18.6% |
| 일반 | dict 읽기 | +5.3% | +19.2% |
| 일반 | dict 쓰기 | +7.5% | +15.7% |
| Free-threaded | NumPy 읽기 | +18.8% | +17.3% |
| Free-threaded | NumPy 쓰기 | +11.6% | +16.8% |
| Free-threaded | dict 읽기 | +3.3% | +4.0% |
| Free-threaded | dict 쓰기 | −2.3% | −16.4% |

[클라이언트별 처리량과 사용한 API](./client-comparison.md)

## 동일 처리량에서 2,000키 NumPy 읽기

Ncloud 재측정에서 일반 CPython은 초당 6만 행, free-threaded는 초당 9만 행을 처리했습니다. **CPU 시간·최대 상주 메모리(RSS)·p99 지연 ↓ 낮을수록 좋습니다.**

| CPython | 지표 ↓ | 0.14.4 대비 | 공식 SDK 대비 |
| --- | --- | ---: | ---: |
| 일반 | 행당 CPU 시간 | −6.1% | −38.7% |
| 일반 | 최대 RSS | +10.7% | −34.7% |
| 일반 | p99 지연 | −1.9% | −47.6% |
| Free-threaded | 행당 CPU 시간 | −1.7% | −43.1% |
| Free-threaded | 최대 RSS | +7.3% | −40.2% |
| Free-threaded | p99 지연 | +1.9% | −48.9% |

[500·1,000·2,000키 상세 비교](./ncloud-equal-rate.mdx) · [동시 호출 수에 따른 메모리 사용량](../guides/migration-0.15.md#memory-under-concurrent-batch-load)

## 비동기 쿼리 {#async-queries}

12,000행을 비동기 목록으로 수집하는 데 걸린 시간은 0.14.4 대비 일반 CPython에서 **38.7%**, free-threaded에서 **22.6%** 줄었습니다. 0.15에서 추가된 `async for`로 같은 행을 순회하면 공식 SDK가 0.15보다 각각 **9.97배**, **4.70배** 오래 걸렸습니다. [조회 방식별 시간](./client-comparison.md#full-set-queries) · [비동기 순회 프로파일](./async-stream-profile.md)
